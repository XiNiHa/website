DX 엔지니어로서 고객사 개발자가 사용하는 결제 SDK부터 사내 FE 챕터의 기반 툴링까지,
회사 안팎의 개발 환경과 성능을 개선하는 일에 집중하여 전방위적으로 기여했습니다.

- **JS 결제 SDK 성능 및 유지보수성 개선**
  기존 SDK는 jQuery 의존성을 가진 단일 스크립트로 구성되어 있었으며,
  지속적 난개발로 인한 유지보수성 악화 및 번들 크기 증가 등의 문제를 겪고 있었습니다.
  이를 해결하기 위해 jQuery 의존성을 걷어내고, ESM 없이(IE11 지원) 기능별 lazy loading이 가능한
  SWC/esbuild 기반 커스텀 모듈 시스템을 설계 및 구성하는 작업을
  문제 제기부터 실행, 검증까지 전 프로세스를 주도하여 진행했습니다.
  해당 개선으로 100KB 이상의 번들 크기 절감을 이루었으며,
  모듈화된 코드베이스 덕에 신규 결제대행사 연동 등의 작업 시에도 팀 전체의 속도가 크게 향상되었습니다.
- **커스텀 결제창 UI 재개발**
  기존 결제창 UI는 리액트 SPA로 개발되어 초기 로딩 속도 측면에서 문제를 겪고 있었는데,
  엣지 스트리밍 SSR과 서버 RPC를 활용하면 이 문제를 가장 잘 해결할 수 있다고 판단하여,
  당시 시점에 해당 기능들을 가장 잘 지원하던 프레임워크인 SolidStart를 채택했습니다.
  결과적으로 일반적인 상황에서 0.3초대의 FCP 수치를 달성할 수 있었고,
  안정성 측면에서도 월 30만건 이상의 결제 요청을 문제 없이 처리했습니다.
- **관리자콘솔 개발 환경 개선**
  기존 콘솔은 SPA에 가까운 역할을 하고 있음에도 불구하고 Next.js SSG를 사용하고 있었고,
  이로 인해 빌드 시간이 늦어지고 불필요하게 SSG를 고려하여 개발해야 하는 등의 생산성 문제가 있었습니다.
  이를 해결하기 위해 제품 전체를 Vite로 전환했고, 빌드 시간 단축 등의 성과를 이루었습니다.
  이외에도 Storybook/TypeScript 등 낙후된 의존성들의 버전을 최신화하거나,
  치솟는 복잡도와 번거로운 사용법 등으로 골머리를 앓던 Sass + CSS Modules 기반 스타일링의 대안으로
  UnoCSS를 도입하며 호환 레이어를 구성하는 등, 개발 환경 전반을 개선했습니다.
- **전사 GraphQL/Relay 도입 주도**
  MSA 상에서 API Gateway 도입을 통한 FE DX 향상을 논의하는 과정에서
  정규화 캐시 등 프론트엔드 관점에서의 강점들을 근거로 GraphQL/Relay 도입을 건의 및 적극 주도했습니다.
  팀 내 원활한 기술 도입을 위해 챕터 구성원들을 대상으로 온보딩 세션을 진행하거나,
  Scala 기반 GraphQL Gateway 서버의 코드 구조를 정립하거나,
  Concurrent Features 활용을 위해 SSE 기반으로 Relay의 `@defer` 지원을 연동하는 등의 작업을 통해
  팀원 모두가 GraphQL을 어려움 없이 다룰 수 있도록 지원했습니다.
- **커스텀 SVG 차트 컴포넌트 구현**
  신규 애널리틱스 서비스 개발 과정에서 반응형 디자인, 애니메이션, sticky한 axis 레이블 등
  기획/디자인 측에서의 기능 및 UX 요구사항 충족을 위해 SVG 차트 컴포넌트를 직접 구현했습니다.
  적절한 Framer Motion과 스크롤 가상화 활용을 통해 다량의 데이터를 다룰 때도 성능 저하를 최소화했고,
  재사용성을 고려한 설계 덕에 추후 타 페이지에서도 동일 컴포넌트를 공유할 수 있었습니다.
